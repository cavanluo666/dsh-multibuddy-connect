WorkBuddy 多账号：池化自动轮换（一个号限流自动换下一个）

背景
此前每个 WorkBuddy 变体只能登一个账号（一变体一份凭据文件）。本提交让它支持
同一产品下的多个账号，并在某个账号被限流/额度耗尽时自动切换到下一个。
模型选择器里仍然只有一个分组 —— 池化对用户透明，这正是"池"的意义。

新增三个模块（共 52 个测试）
- src/pool.ts           账号池：多账号记录、冷却记账、指数退避、持久化
- src/pool-failover.ts  轮换：最多每个账号试一次，只对"换号可能成功"的失败换号
- src/account-manager.ts 账号管理：拥有 N 个凭据存储，对外暴露"当前活跃账号"

换号判据（复用已有的 classifyUpstreamError，不新造分类）
  soft_rate    限流       → 冷却 1 分钟起、指数退避、上限 30 分钟 → 换号
  hard_credit  额度耗尽    → 冷却 24 小时                      → 换号
  session_dead 登录失效    → 永久停用并提示重新登录              → 换号
  server / client / activation_required → 不换号
后者换号也一样失败，遍历池只会把一个错误放大成 N 个、并拖延用户该看到的报错。

接入方式（关键：现有调用点一行未改）
- VariantRuntime.store 改为 GETTER，返回池里当前活跃账号的 store。
  现有 12 处 runtime.store.xxx 因此语义不变，全部继续正确。
- shim 未配池时走原来的 resolve + chatStream 路径，一行逻辑不变。
  池是加法而非替换，单账号安装不受任何影响。
- 登录改为"追加"而非覆盖：管理器的键是身份（uid:enterpriseId），
  同一账号重登原地更新，不同账号新增一槽。
- 登出只登出当前活跃账号（用户裁决），其余账号接管。
- 新登录的账号自动设为活跃。
- 启动时先发现磁盘上已有的账号，再让任何东西读"当前账号"。

账号文件布局
  账号 0 → .workbuddy-auth.json     （历史路径不变，升级不会被当成登出）
  账号 1 → .workbuddy-auth-a2.json
  账号 2 → .workbuddy-auth-a3.json
  池状态 → .workbuddy-auth-pool.json

界面
配置卡片新增「账号池」区块：每个账号显示昵称、是否活跃、冷却倒计时与原因、
累计限流次数、上次成功时间。单账号用户看不到该区块（宿主在只有一个账号时
就不下发 pool 数据）。模型选择器仍是单一分组。

过程中修掉的缺陷
- 同账号重登时昵称更新但 label 不更新（服务端改名永远到不了卡片）
- 补上池相关模块的主入口导出（此前外部拿不到这些 API）

759 个测试通过；服务端与客户端类型检查零错误。
