修复插件无法加载：客户端 bundle 注册 id 与包名不一致

症状
重启 DSH 后 web boot 报「1 entry did not activate / import failed」，插件整个
不激活。构建通过、宿主半边单独导入也正常，所以错误在客户端 bundle。

根因
tsdown.config.ts 把客户端 bundle 的注册 id 写成字面量
'dsh-workbuddy-connect'，而包已改名为 dsh-multibuddy-connect。
DSH 的 ClientBundleRegistration.id 文档明确要求「must match the graph row
being executed」——不匹配时 bundle 不会被 materialize，且构建期不报错。

同类隐患一并排查并修正
同一个包名还被另外两处以字面量硬编码，都会静默失败：
- src/paths.ts 用它匹配 profile 的依赖声明，写死旧名会让
  discoverProfileDir() 找不到 web profile，插件改而把凭据写到
  $DSH_HOME，静默遗弃用户已有的登录态；
- src/client/index.tsx 用它作 plugins.bundle.config 槽位键，
  插件管理页正是读这个键决定要不要渲染本插件的设置区块。

修法（消除整类问题，而非只修一处）
新增 src/plugin-name.ts，包名由 tsdown/vitest 的 define
__DSH_PLUGIN_NAME__ 从 package.json 注入，成为唯一来源：
- tsdown.config.ts: PLUGIN_ID = MANIFEST.name
- vitest.config.ts: 同步该 define
- client/index.tsx、host-heartbeat.ts、bin.ts 改用该常量
- paths.ts 同时接受新名与上游旧名，兼容升级而来的 profile

保留不变
- 数据目录名 .dsh-workbuddy-connect 与 /plugins/dsh-workbuddy-connect/*
  路由前缀：改动会遗弃用户已保存的凭据、目录与设置，且宿主与客户端本就
  引用同一组常量，功能上无碍。

测试
新增 tests/plugin-name.spec.ts，把常量钉在 package.json、tsdown 配置与
cordis 补丁行上，并断言 tsdown 里不再出现字面量 id——下次改名若只改一半，
会在测试期带着解释失败，而不是变成一个静默不加载的插件。
host-heartbeat.spec.ts 的断言改为对齐单一来源。

668 个测试通过；服务端与客户端类型检查零错误。
